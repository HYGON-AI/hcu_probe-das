dcu_probe pt_compare(consistent_check=True, backend=fsdp) —— 训推一致比对算法流程标注

本页 = verl 0.8.0 FSDP 后端。训推一致性里 npu = 训练侧 dump（HF 风格 FSDP，命名 embed_tokens / q_proj·k_proj·v_proj（分开）/ o_proj / gate_proj·up_proj（分开）/ down_proj / RMSNorm），bench = 推理侧 dump（das vllm 0.11）。同一个 prompt 的 prefill 前向理论上数值一致，但两侧是异构框架——算子命名、拆分粒度、shape、出现顺序全不同。默认 compare 的“算子全名对全名”必然配不上。

consistent_check=True 不是“调了个阈值”，而是把默认的 pd.merge(on=CMP_KEY) 整体换成一套语义级异构比对管线：解析裁窗 → 模块名归一映射 → 四元组多对一聚合 merge → 双单调保序 → shape 口径修正。这套管线是 dcu_probe 源码、版本无关——与 verl-0.7-fsdp 版 95% 相同；差异只在推理栈从 das vllm 0.18.1 换到 0.11 带来的“出现顺序”与实测数字。本页标注这条管线在哪几个源码文件、哪几行、每一步抹平哪一类异构。绿色高亮 = 关键新增/专用逻辑。

为什么需要它：普通 compare 在训推场景必然对不上

默认 compare（consistent_check=False）走 acc_compare.py:967 的 pd.merge(npu_df, bench_df, on=[CMP_KEY], how='outer')——算子全名对全名。下面 5 类异构，每一类都会让这种 merge 崩掉；每一类对应一个正交机制去抹平。

范围对齐
① 只留 prefill 主干

抹平「覆盖范围」异构

推理侧一个 request 就只有 prefill 前向；训练侧一个 train_step 却含反向传播 + 最外层模型壳。若不裁，训练侧一大堆算子在推理侧没有对应。

用两条规则给训练侧卡一个窗口：从 Embedding（fsdp）/ VocabParallelEmbedding（megatron）的 forward 起开解析，到 Qwen2Model/GPTModel 顶层的 backward 止停解析。只留和推理 prefill 可比的前向主干。

本页 backend=fsdp：STOP 用 Qwen2Model（Qwen2.5-0.5B）、BEGIN 用 HF Embedding。推理侧（Bench）不裁——它天然只有 prefill 前向。

② 叫法归一

抹平「算子命名」异构

训练框架和推理框架对同一算子叫法不同（q_proj vs qkv_proj、linear_fc2 vs down_proj）。把叶子名按映射表改写，写进 MODULE_MAPPING 列。

FSDP 只映射训练侧：推理侧本来就叫融合名 qkv_proj，直接取叶子名即可。本页走这条分支（backend==FSDP）。

MEGATRON 双侧都映射：mcore（linear_qkv…）和 vllm（qkv_proj…）命名都跟标准 HF 不一样，两边都要归一。

映射后，「3 个训练算子」和「1 个推理融合算子」落到同一个语义 key，为 ③ 的多对一聚合铺路。

③a 语义 merge · ③b 多对一聚合

抹平「拆分粒度」异构

(a) 四元组 merge：不再靠算子全名，而是按 [前反向, 后缀, 层号, 映射后模块名] 四元组对齐——语义对齐而非字符串对齐。

(b) groupby 聚合：训练侧 q/k/v 三算子 → 推理侧 1 个 qkv_proj，是多对一。FSDP 按推理侧 op_name_y 分组，把三行的 op_name/dtype/shape/summary/data_name 用 ; 拼成一行；MEGATRON 方向相反。本页走 backend==FSDP 分支。

这就是华为文档说的“自动 cat SP 切片 / 融合算子”的底层实现——不是真去 concat 张量，而是把多个统计量行聚合成一行再逐项比。

③c 保序 · 冲突即报错

抹平「出现顺序」异构

聚合 + concat 后行顺序乱了。这个算法用双指针重排，强制最终顺序同时满足「训练侧原始序 npu_pos 递增」和「推理侧原始序 bench_pos 递增」（未配对行 NaN 排最后）。

修法B
④ shape 口径对齐

抹平「shape」异构

默认 ShapeErrChecker 字符串严格比 shape，[1,S,H] != [S,H] 会把可比算子全判 error。替换版做三件事：

1. squeeze：去掉所有值为 1 的维，抹平 batch=1 差异（FSDP 训练 [1,S,H] ↔ 推理 packed [S,H]）。
2. FSDP 跳融合：bench_name 含 qkv/gate_up 的聚合行直接 continue（已多对一拼过，shape 本就对不上）。
3. MEGATRON 降维：训练 3 维 [d0,d1,d2] 合并后两维成 [d0, d1*d2] 再比（mcore [S,B,H] vs vllm [S*B,H]）。

0.8 FSDP 语境：修法B 已合入 dcu_probe 主仓 —— statistics + consistent_check 会自动挂 VerlShapeErrChecker、自动 squeeze [1,S,H]↔[S,H]，用含此修正的 dcu_probe whl 即可，不必手改源码（compare 跑通 98 算子即证）。验证：python3 -c "from dcu_probe.core.compare.indicator_analysis.algorithm import VERL_STATISTICS_CHECKERS, VerlShapeErrChecker" 不报错。

关键：statistics 和 tensor 两种 dump 模式都挂（VERL_STATISTICS_CHECKERS + VERL_TENSOR_CHECKERS）。以前只挂 tensor、statistics 漏挂 → 全 shape error、配对几乎为 0，这就是 CLAUDE.md 反复提的“修法B”补丁；现已进主仓。另：Megatron-LM 必须在 PYTHONPATH（VerlShapeErrChecker 依赖）。

串起来：一句话 + 与实测现象呼应

consistent_check=True（backend=fsdp）= 解析裁窗（留 prefill 主干） → 模块名归一映射（叫法对齐） → 四元组多对一聚合 merge（融合算子对齐） → 双单调排序（0.8 一次即过、无需过滤） → shape squeeze/跳融合（口径对齐） 的一整套异构框架比对管线。

它解释了 verl 0.8.0 FSDP 后端几个实测现象的根——这些不是 bug，是管线对齐后暴露出的“真差异”或“方法学必须排除项”（Qwen2.5-0.5B，排整层 + IdentityOp + act_fn 后：可比叶子算子 98 个，sdpa 97/98=98.98% <1%、中位 0.121%；eager 96/98=97.96% <1%、中位 0.199%）：

o_proj sdpa 1.78% / eager 2.67% 小尾巴
