run_fsdp_compare.py 代码逻辑 —— 用 dcu_probe 的 pt_compare(backend=fsdp) 复核 verl 0.8 FSDP 训推一致性

这个脚本本身不算精度 —— 它做的是「把训练侧、推理侧的 dump 配对好,直接交给 dcu_probe 的官方比对工具 pt_compare 去逐算子算误差」。

真正发挥效果的 dcu_probe 工具 = pt_compare;脚本只有 4 步、无过滤:前 2 步为 pt_compare 准备能对齐的输入,第 3 步才调 pt_compare,第 4 步读它的结果。0.8 FSDP 推理用 das vllm 0.11 → dump 模块序干净 → 不需要 0.7 那步过滤(这是 0.8 相对 0.7 FSDP 的最大简化,和 Megatron 后端同一套思路,因两者都用 das vllm 0.11)。

★ 核心工具:dcu_probe 的 pt_compare(官方精度比对 API,两后端共用)

pt_compare 是什么、发挥什么效果

来自 dcu_probe.pytorch.compare.pt_compare(= 华为 msprobe compare 的 DCU fork)。它是 dcu_probe 提供的官方逐算子精度比对能力,本脚本第 3 步调的就是它:

# 训练侧 dump ↔ 推理侧 dump,逐算子比对(FSDP 后端) pt_compare({"npu_path": 训练侧dump.json, "bench_path": 推理侧dump.json}, out, consistent_check=True, backend="fsdp")

它内部干这几件事(效果):

  • 读两侧 dump.json → 建两张算子表(NPU=训练侧、Bench=推理侧)。
  • consistent_check=True → 走 verl 训推一致专用比对算法(而非普通逐 tensor 比;也是修法B 的 VerlShapeErrChecker 生效开关)。
  • backend="fsdp" → 用 FSDP_MODULE_MAP 把 HF 命名映射到 vllm 命名(q/k/v_proj → qkv_proj、gate/up_proj → gate_up_proj)。
  • consistent_match → dual_monotonic_sort 把两侧算子按位置单调对齐 → 0.8 das vllm 0.11 模块序干净,这一步一次就过(不像 0.7 的 das vllm 0.18.1 有 72 个交错模块要先过滤才不崩)。
  • 逐算子算 NormRelativeErr(Norm 相对误差)→ 落 compare_result_*.xlsx。

关键:因为 0.8 FSDP 和 Megatron 后端都用 das vllm 0.11、dump 模块序干净,脚本可以把配对好的两侧 dump 直接喂 pt_compare,省掉 0.7 的过滤步 —— 4 步搞定,和 Megatron 后端 run_megatron_compare.py 同一套骨架,只差 backend 参数。

整脚本数据流(4 步,无过滤):
① 按 request_id 配对两侧 dump → ② 挑同 prompt 完整 prefill 样本 → ③ 直接调 pt_compare(无过滤) → ④ 读 xlsx 排除+统计(98 叶子算子,sdpa 97/98 <1%)
①按 request_id 配对两侧 dump给 pt_compare 找到"同一个 prompt 的两份 dump"

配对

把两侧对上号

pt_compare 一次只比一对 dump.json(一个训练前向 vs 一个推理前向)。这步用 request_id 把两侧对上:推理侧从 dispatch_log 找、训练侧从 update_actor_log 找,分别建成 gen[rid] / train[rid] 两张表。

只取单 request(推理 len(reqs)==1 / 训练 num_requests==1)的 prefill —— 多 request 拼 batch 的 dump 是混合张量,无法逐层比。das 会给 id 加 -<8hex> 后缀,strip 去掉才对得齐。

②挑同 prompt 的完整 prefill 样本保证 pt_compare 比的是同一个东西

对齐

token 数一致 = 真·同 prompt

tok() 取 embed_tokens 的输入 token 数。FSDP 训练侧是 HF 风格命名(embed_tokens,不是 mcore 的 word_embeddings),推理侧 vllm 也叫 embed_tokens —— 所以两边都用同一个子串 ["embed_tokens"] 取 token 数。

两侧相同,才说明喂进模型的是同一个 prompt 的完整 prefill(没被 prefix cache 截断、没被 batch 拼)。选一个这样的 rid,拿它的训练 dump(train[rid])和推理 dump(gen[rid])去比 —— 这就是要喂给 pt_compare 的那一对。

dcu_probe 工具

官方逐算子比对就在这一行

前 2 步全是铺垫,这一行才是真正发挥效果的 dcu_probe 工具。bench_path 直接传 gen[rid] —— 没有 0.7 的过滤步。因为 0.8 用 das vllm 0.11,推理 dump 模块序干净,dual_monotonic_sort 一次就能把两侧单调对齐,不会崩。

脚本 vs 工具的分工:脚本负责"配对好、挑对样本",pt_compare 负责"命名映射(FSDP_MODULE_MAP)+ 单调对齐 + 算 Norm 相对误差 + 出 xlsx"。

能直接喂的前提 = 修法B 已生效(见下卡)—— 否则 FSDP 训练 [1,S,H] vs 推理 [S,H] 会全判 shape error、配对≈0。

★B修法B:FSDP statistics + consistent_check 的 shape squeeze 盲区FSDP 特有先决,支撑③能直接喂

VERL_STATISTICS_CHECKERS = [InfNanErrChecker, RelativeErrChecker, RequiresGradErrChecker, ParametersErrChecker,
DTypeErrChecker, VerlShapeErrChecker, RelativeWarnChecker]
# 修法B 本体:calculator.py 的 _add_algorithm,STATISTICS 分支加 consistent_check
def _add_algorithm(self):
if self.mode == CompareMode.STATISTICS.value:
if self.consistent_check: # ← 新增这两行
checkers = VERL_STATISTICS_CHECKERS # verl 训推一致用带 squeeze 的版本
elif self.parallel_merge:
checkers = STATISTICS_CHECKERS_PARALLEL_MERGE
else:
checkers = STATISTICS_CHECKERS
for checker in checkers:
self.add_algorithm(checker())
FSDP 特有

[1,S,H] vs [S,H] 的容差

FSDP 训练侧 dump 张量是 [1,S,H](HF eager 里 unsqueeze(0)),推理 vllm 是 [S,H](packed)。dcu_probe 的 squeeze 容差检查器 VerlShapeErrChecker 早期只挂 task=tensor;而本 skill 用的 task=statistics(L0 统计量)恒用严格 ShapeErrChecker → 两侧 shape 字符串不等 → 几乎全判 shape error、可比配对≈0。

修法B = 让 statistics + consistent_check 也走 VerlShapeErrChecker:加 VERL_STATISTICS_CHECKERS 列表 + calculator._add_algorithm 的 if self.consistent_check 分支。已合入 dcu_probe 主仓 —— 用含此修正的包即可,验证命令打印 OK 就能直接跑。

另一前置:Megatron-LM 必须在 PYTHONPATH(VerlShapeErrChecker 链路依赖它,缺则 import 深处报错)。

④读 xlsx,排除结构性不可比 + 统计把 pt_compare 的结果整理成结论
df = pd.read_excel(sorted(glob.glob(out + "/*.xlsx"))[-1]) # pt_compare 出的报告
m = df[df["NPU Name"].notna() & df["Bench Name"].notna()].copy() # 双边 match 的行
m["nerr"] = m["NormRelativeErr"].apply(p2f)
nm = m["NPU Name"].astype(str)

EXCLUDE = "Qwen2DecoderLayer|Qwen2MLP|Qwen2Attention|IdentityOp|act_fn|SiLU"
is_excl = nm.str.contains(EXCLUDE, na=False, regex=True)

print("<1%%: %d/%d" % ((real["nerr"] < 1).sum(), real["nerr"].notna().sum())) # 97/98
统计

排除结构性不可比,报叶子算子分布

pt_compare 会把所有算子都列进 xlsx,包括结构性不可比的:整层 wrapper(输出是残差和)、IdentityOp、act_fn 融合算子。这步先取双边 match 的行,再用 EXCLUDE 正则排掉它们,只统计带 output 的真叶子算子(o_proj / down_proj / layernorm / embed / norm)。

结果:可比叶子算子 98 个 —— sdpa 97/98 <1% 中位 0.121%、eager 96/98 中位 0.199%;embed 两侧完全相同(误差 0);唯一 >1% 是 o_proj(train attn kernel vs vllm attn kernel 的代价,非 bug)。

排排除口径 —— 哪些算子不进可比集(脚本注释原文)保持透明,方法学正当
# 排除项(都不是"训推可比的叶子算子",列出来保持透明):
# - 整层 wrapper(Qwen2DecoderLayer/MLP/Attention):output=残差和,两侧结构/捕获点不同,relative err 失真
# (megatron 口径也不比 TransformerLayer)
# - IdentityOp:融合占位算子
# - act_fn(SiLU/SiluAndMul):融合算子不可比 —— HF act_fn=silu(gate) 单独,
# vllm act_fn=SiluAndMul=silu(gate)·up,算的是不同张量。
# 真正等价的比较点是 down_proj(两侧都吃 silu(gate)·up)。
EXCLUDE = "Qwen2DecoderLayer|Qwen2MLP|Qwen2Attention|IdentityOp|act_fn|SiLU"
口径

三类结构性不可比 + FSDP 少比 qkv/gate_up

整层 wrapper:Qwen2DecoderLayer/MLP/Attention 的 output 是残差和(massive activation),两侧捕获点不同 → relative err 失真。IdentityOp:融合占位算子。act_fn 融合:HF 单算 silu(gate),vllm 是 SiluAndMul=silu(gate)·up,算的是不同张量(误差 80-141%)—— 真正等价的比较点是 down_proj(两侧都吃 silu(gate)·up)。

⚠️ FSDP 比 Megatron 少比 qkv / gate_up:HF 训练侧 q/k/v_proj、gate/up_proj 是分开的,与推理 vllm 的融合 qkv_proj/gate_up_proj 配不上(shape/语义不同)→ 不进可比集。这不是 bug,是 HF 分开 vs vllm 融合;可比集只剩 o_proj / down_proj / layernorm / embed / norm 共 98 个。

③ 二者跑的是同一个 pt_compare
run_fsdp_compare.py 与 run07_filtered.py 调的都是 dcu_probe 官方 pt_compare(backend="fsdp"),底层比对算法、命名映射(FSDP_MODULE_MAP)、排除口径完全一致 —— 唯一差别就是「喂之前要不要过滤」,而这取决于推理侧用的是 das vllm 0.11(干净)还是 0.18.1(有交错模块)。两者结论互相印证:0.8 的 98 个叶子 sdpa 97/98 <1% ≈ 0.7 过滤后的 98/98 <1%。
