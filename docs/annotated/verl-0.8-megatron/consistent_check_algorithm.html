hcu_probe pt_compare(consistent_check=True, backend=megatron) —— 训推一致比对算法流程标注 · verl 0.8.0 Megatron 后端

训推一致性里 npu = 训练侧 dump（mcore + TE + Megatron-LM core_v0.13.1），bench = 推理侧 dump（das vllm 0.11）。同一个 prompt 的 prefill 前向理论上数值一致，但两侧是异构框架——算子命名（mcore/TE vs vllm）、拆分粒度、shape、出现顺序全不同。默认 compare 的“算子全名对全名”必然配不上。

consistent_check=True 不是“调了个阈值”，而是把默认的 pd.merge(on=CMP_KEY) 整体换成一套语义级异构比对管线：解析裁窗 → 模块名归一映射 → 四元组多对一聚合 merge → 双单调保序 → shape 口径修正。本页标注这条管线在哪几个源码文件、哪几个函数、每一步抹平哪一类异构。megatron 后端走 backend="megatron" 分支（用 MEGATRON_MODULE_MAP），绿色高亮 = 关键新增/专用逻辑。

与 0.7 的唯一区别在“钩子挂哪”，不在“compare 怎么比”。0.8.0 的训练侧 dump 钩子挂在 NEW engine 的 verl/workers/engine/megatron/transformer_impl.py（MegatronEngineWithLMHead.forward_step 的 forward_fn 前后），而 0.7.1 挂在 legacy 的 megatron_actor.py。两版 dump 出来的 dump.json 结构相同——本页这条 consistent_check 五段管线是 hcu_probe 源码、版本无关，0.8 与 0.7 逐段一致。

为什么需要它：普通 compare 在训推场景必然对不上

默认 compare（consistent_check=False）走 acc_compare.py 的 pd.merge(npu_df, bench_df, on=[CMP_KEY], how='outer')——算子全名对全名。下面 5 类异构，每一类都会让这种 merge 崩掉；每一类对应一个正交机制去抹平。

五段管线总览npu=训练bench=推理

从两侧 dump.json 到逐行相对误差，数据依次流过 5 段。每段只干一件事、只抹平一类异构；前一段做错，compare 要么配对为 0、要么比出假 diff。这条管线与 FSDP 后端共用，只在 ② 用 MEGATRON_MODULE_MAP、③b 按训练侧聚合、④ 走 mcore 降维分支上有别。

范围对齐
① 只留 prefill 主干

抹平「覆盖范围」异构

推理侧一个 request 就只有 prefill 前向；训练侧一个 train_step 却含反向传播 + 最外层模型壳。若不裁，训练侧一大堆算子在推理侧没有对应。

用两条规则给训练侧卡一个窗口：从 VocabParallelEmbedding（megatron）的 forward 起开解析，到 GPTModel 顶层的 backward 止停解析。只留和推理 prefill 可比的前向主干。（FSDP 对应的是 Embedding → Qwen2Model。）

推理侧（Bench）不裁——它天然只有 prefill 前向。

② 叫法归一

抹平「算子命名」异构

训练框架和推理框架对同一算子叫法不同（mcore linear_qkv vs vllm qkv_proj、linear_fc2 vs down_proj）。把叶子名按映射表改写，写进 MODULE_MAPPING 列。

MEGATRON 双侧都映射：mcore（linear_qkv / linear_proj / linear_fc1…）和 vllm（qkv_proj / o_proj / gate_up_proj…）命名都跟标准 HF 不一样，两边都要归一。代码里“取叶子名”的捷径只对 FSDP 推理侧生效，megatron 不走。

映射后，训练侧 mcore 算子和推理侧 vllm 算子落到同一个语义 key，为 ③ 的四元组匹配铺路。

核心匹配
③a 语义 merge · ③b 多对一聚合

抹平「拆分粒度」异构

(a) 四元组 merge：不再靠算子全名，而是按 [前反向, 后缀, 层号, 映射后模块名] 四元组对齐——语义对齐而非字符串对齐。

(b) groupby 聚合：megatron 的多对一主要来自 SP 沿序列切片（每 rank 一段）+ mcore 的融合结构。backend==MEGATRON 走按训练侧 op_name_x 分组，把对应的多行 op_name/dtype/shape/summary/data_name 聚合成一行；方向与 FSDP（按 op_name_y）相反。

这就是华为文档说的“自动 cat SP 切片 / 融合算子”的底层实现——不是真去 concat 张量，而是把多个统计量行聚合成一行再逐项比（need_cat + BACKEND_CAT_RULES 按 seq 维 concat 而非平方和）。

def dual_monotonic_sort(match_result, pos1, pos2): # O(n log n) 双指针
order1 = match_result.sort_values(pos1).index # 按训练侧位置排
order2 = match_result.sort_values(pos2).index # 按推理侧位置排
while len(result_idx) < n:
min1, min2 = order1[i], order2[j] # 两序列当前最小未用行
for k in (min1, min2):
# 该行若在某列非 NaN,必须同时是那列的当前最小
if not pd.isna(row[pos1]) and k != min1: ok = False
if not pd.isna(row[pos2]) and k != min2: ok = False
if ok: picked = k; break

③c 保序 · 冲突即报错

抹平「出现顺序」异构

聚合 + concat 后行顺序乱了。这个算法用双指针重排，强制最终顺序同时满足「训练侧原始序 npu_pos 递增」和「推理侧原始序 bench_pos 递增」（未配对行 NaN 排最后）。若某行在两列上的相对位置互相矛盾，就 raise。

megatron 0.8（das vllm 0.11）在这一步直接通过、无需任何过滤。推理侧 dump 的模块序很干净：只有 prefill 前向主干，没有夹杂训练侧不存在的交错 kernel，所以“两侧位置同时单调递增”天然成立，run_megatron_compare.py 里没有 bench-only 过滤步、一次就过。

对照：FSDP 0.7 用的是 das vllm 0.18.1，会多 dump 数十个训练侧没有的交错模块（Triton attn / cache / rotary），夹在推理序列中间会让此处物理上无法保序而 raise，必须先跑 run07_filtered.py 过滤掉这些 bench-only 模块再喂 pt_compare。megatron 0.8 用 0.11，没有这个坑。

④ shape 口径对齐

抹平「shape」异构

默认 ShapeErrChecker 字符串严格比 shape，[S,1,H] != [S,H] 会把可比算子全判 error。替换版做三件事：

1. squeeze：去掉所有值为 1 的维，抹平 mcore 整层 [S,1,H] 与推理 [S,H] 的差异。
2. FSDP 跳融合：bench_name 含 qkv/gate_up 的聚合行 continue（FSDP 专属分支，megatron 不触发）。
3. MEGATRON 三维降二维：训练 3 维 [d0,d1,d2] 合并后两维成 [d0, d1*d2] 再比——即 mcore [S,B,H]（关 SP 后 [344,1,4096] 等）降成 [S, B*H]，与 vllm packed [S*B,H] 对齐。这是 megatron 后端能过 shape 门的关键分支。

关键：statistics 和 tensor 两种 dump 模式都挂（VERL_STATISTICS_CHECKERS + VERL_TENSOR_CHECKERS）。以前只挂 tensor、statistics 漏挂，就是 CLAUDE.md 反复提的“修法B”补丁；该补丁已合入 hcu_probe 主仓 whl，装官方包即带此逻辑，无需再改源码。训推一致 dump 走 L0+statistics，靠的正是 statistics 这一挂。

串起来：一句话 + 与实测现象呼应

consistent_check=True（backend=megatron） = 解析裁窗（留 prefill 主干） → MEGATRON_MODULE_MAP 归一映射（叫法对齐） → 四元组多对一聚合 merge（cat SP 切片） → 双单调排序（保序、0.11 直接过） → shape squeeze/三维降二维（口径对齐） 的一整套异构框架比对管线。

它解释了 verl 0.8.0 megatron 后端（Qwen3-8B，3 个不同长度 prompt 72/80/112 tok）实测的几个现象——这些不是 bug，是管线对齐后暴露出的“真一致”“真差异”或“方法学必须排除项”：

1083 真算子 99.4% <1% · 中位 0%
机制 ①–④ 对齐后，真算子（embed + linear_qkv/linear_proj/linear_fc1/linear_fc2/core_attention）output NormRelativeErr 99.4% <1%、中位 0%，embed 两侧 Norm 完全相同——0 个真叶子发散，这是训推一致的直接证据。2 个独立样本 s0/s1 完全一致。
整层 TransformerLayer 量级差 ~4000x
超 1% 的行全是 TransformerLayer 整层聚合输出：训练侧残差流 massive-activation max~2.2e4 vs 推理侧 ~5.7，shape [S,1,H] vs [S,H]——层封装含 SP/residual、非 normed 算子，融合整层不该逐 tensor 比，方法学排除，不是 bug（不同模块边界 + Qwen 残差 massive-activation 现象）。
IdentityOp 恒等占位不比
megatron 把 layernorm 融进 TELayerNormColumnParallelLinear，层内 input_layernorm/pre_mlp_layernorm 是恒等占位、无真 norm 输出，不对应 vllm 的真 RMSNorm——IdentityOp 不参与比对，这是 mcore/TE 融合结构的必然，非 dump 漏采。
final_layernorm 映射未覆盖 → 手动验
官方 MEGATRON_MODULE_MAP 没写 final_layernorm→model.norm，pt_compare 默认不比它。但可手动 probe 两侧 Norm——实测 1320 == 1320 一致。“映射表没覆盖”≠“不一致”，只是自动管线的覆盖边界。
★诚实定界：可比子集一致 ≠ 逐 tensor 全一致
训推一致 = 可比叶子算子 + 激活统计量一致（1083 真算子 99.4% <1%、中位 0%），不是全部 tensor 一致。直读官方 compare 的 4867 行：3927 pass（253 权重同源必同 + 3673 激活统计量 + 1）、939 “error” 里 903 是 requires_grad 元数据差（训练 True/推理 False，benign）、1 是 int dtype、35 是整层 TransformerLayer/IdentityOp。别据此夸成“逐 tensor 全一致”。
