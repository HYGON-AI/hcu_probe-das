run_megatron_compare.py 代码逻辑 —— 用 dcu_probe 的 pt_compare(backend=megatron) 复核 verl 0.8 Megatron 训推一致性

这个脚本本身不算精度 —— 它做的是「把训练侧(mcore/TE)、推理侧(das vllm)的 dump 配对好、挑对样本,再交给 dcu_probe 的官方比对工具 pt_compare 去逐算子算误差」。

真正发挥效果的 dcu_probe 工具 = pt_compare;脚本的 4 步里,前 2 步都是在「为 pt_compare 准备能对齐的输入」,第 3 步才调 pt_compare,第 4 步读它的结果。与 0.7 megatron 几乎一样 —— 都用 das vllm 0.11、都是 4 步无过滤、都调同一个官方 pt_compare + MEGATRON_MODULE_MAP;差别只在验证模型(0.8 = Qwen3-8B)与结果规模。

★ 核心工具:dcu_probe 的 pt_compare(官方精度比对 API,backend=megatron)

pt_compare 是什么、发挥什么效果

来自 dcu_probe.pytorch.compare.pt_compare(= 华为 msprobe compare 的 DCU fork)。它是 dcu_probe 提供的官方逐算子精度比对能力,本脚本调的就是它:

# 训练侧 dump(mcore/TE)↔ 推理侧 dump(das vllm 0.11),逐算子比对 pt_compare({"npu_path": 训练侧dump.json, "bench_path": 推理侧dump.json}, output_path, consistent_check=True, backend="megatron")

它内部干这几件事(效果):

  • 读两侧 dump.json → 建两张算子表(NPU=训练侧、Bench=推理侧;方向反了就 match 不上,证据 acc_compare.py:786-787 成对 engine='train'/engine='infer')。
  • consistent_check=True → 走 verl 训推一致专用比对算法(而非普通逐 tensor 比)。
  • backend="megatron" → 用 MEGATRON_MODULE_MAP 把 mcore/TE 命名映射到 vllm 命名,含 10 条:word_embeddings→embed_tokens、self_attention→self_attn、linear_qkv→qkv_proj、q_layernorm→q_norm、k_layernorm→k_norm、core_attention→attn、linear_proj→o_proj、router→gate、linear_fc1→gate_up_proj、linear_fc2→down_proj。
  • consistent_match → dual_monotonic_sort → 把两侧算子按位置单调对齐;张量并行(SP)切片由 need_cat+BACKEND_CAT_RULES 按 seq 维自动 cat 回整层再比(不是平方和聚合——SP 把不同 token 分到不同 rank,平方和数学上错)。
  • 逐算子算 NormRelativeErr(Norm 相对误差)→ 落 compare_result_*.xlsx。

关键(megatron 比 FSDP 0.7 简单):megatron 后端推理侧用 das vllm 0.11,dump 里的模块序干净、没有训练侧缺失的交错模块 → 可以直接把配对好的两侧 dump 喂 pt_compare,dual_monotonic_sort 一次就过。而 FSDP 0.7 用 das vllm 0.18.1,推理 dump 多出 72 个交错模块会撑爆对齐,必须先过滤 —— 0.8 megatron 和 0.7 megatron 一样没有那道坎。

整脚本数据流(4 步,无过滤,与 0.7 megatron 同):
① 按 request_id 配对两侧 dump → ② 挑同 prompt 完整 prefill 样本(embed token 数相等) → ③ 调 pt_compare(backend=megatron) → ④ 读 xlsx 排除整层+统计(1083 真算子 99.4% <1%、中位 0%)

配对

把两侧对上号

pt_compare 一次只比一对 dump.json(一个训练前向 vs 一个推理前向)。这步用 request_id 把两侧对上:推理侧从 dispatch_log 找、训练侧从 update_actor_log 找。

只取单 request(推理 len(reqs)==1 / 训练 num_requests==1)的 prefill —— 多 request 拼 batch 的 dump 是混合张量,无法逐层比。das 会给 id 加 -<8hex> 后缀,strip(split "-" 取首段)去掉才对得齐。

megatron 特有:训练侧 request_id 由 ③ 号 patch(llm_server)注入 extra_fields、贯穿到训练侧 micro_batch,再由 update_actor_log 逐样本落 step/rank,这里才配得上 dump_actor/stepN/rankM/dump.json。

对齐

token 数一致 = 真·同 prompt

tok() 取 embed 层 forward.0 的 input_args[0].shape[-1](= 输入 token 数)。megatron 两侧 embed 命名不同:训练侧是 mcore 的 word_embeddings.VocabParallelEmbedding,推理侧是 vllm 的 embed_tokens.VocabParallel —— 所以两边各用各的关键字取。

为什么必须过滤:推理部分 prompt 会被 chunk(dump 粒度),dump_generate/{pid}/step{k} 可能取到不完整 chunk(完整 72 tok 取成 4 tok)。不过滤会拿错配对、误差全是假象 —— 实测过滤前 1~130%、过滤后真算子 99.4% <1%。选一个 token 数相等的 rid,拿 train[rid]/gen[rid] 去比,就是喂给 pt_compare 的那一对。

dcu_probe 工具

官方逐算子比对就在这一行

前 2 步全是铺垫,这一行才是真正发挥效果的 dcu_probe 工具。它读两侧 dump.json,用 consistent_check+backend=megatron 的专用算法把算子对齐(MEGATRON_MODULE_MAP 命名映射 + dual_monotonic_sort 单调对齐 + SP 切片自动 cat),逐算子算 Norm 相对误差,落 xlsx。

方向不能反:npu_path 必须给训练、bench_path 给推理(acc_compare.py:786-787 成对 engine='train'/'infer');反了 module 全 match 不上(报 shape/grad inconsistent)。

直接喂,无过滤:这里把 gen[rid] 直接喂进去 —— das vllm 0.11 模块序干净,dual_monotonic_sort 一次就过,不像 FSDP 0.7 要先剔 72 交错模块。容器要 pip install openpyxl,否则存 xlsx 崩。

④读 xlsx,排除整层+统计把 pt_compare 的结果整理成结论

统计

排除结构性不可比,报叶子算子分布

pt_compare 会把所有算子都列进 xlsx,包括结构性不可比的:整层 wrapper(TransformerLayer 的输出是残差和)、IdentityOp(megatron 把 layernorm 融进 TELayerNormColumnParallelLinear,层内 input_layernorm/pre_mlp_layernorm 是恒等占位)。这步只留带 output、且非 IdentityOp 的真叶子算子输出统计 NormRelativeErr,并首尾抽查 word_embeddings / final_layernorm 两侧 l2norm。

结果(Qwen3-8B,3 个不同长度 prompt 72/80/112 tok 汇总):真算子(embed + qkv/proj/mlp/attention)1083 个 99.4% 误差 <1%、中位 0%、embed 两侧 Norm 完全相同 = 训推一致。单样本 run_megatron_compare.py 跑一对、batch_compare.py 跨样本汇总。final_layernorm 官方映射表未覆盖(无 final_layernorm→model.norm),官方 compare 不比,但手动验两侧 Norm 1320==1320 一致。

诚实定界 + 已知问题(照实说,别夸成"逐 tensor 全一致")

① 训推一致的准确含义 = 可比叶子算子 + 激活统计量一致,不是全部 tensor 一致
直接读官方 pt_compare 的 4867 行 xlsx 复核:3927 pass(253 权重同源必同 + 3673 激活统计量一致 + 1)、939 "error" 里 903 是 requires_grad 元数据差(训练 True/推理 False,benign)、1 是 int dtype(值相同)、35 是整层 TransformerLayer/IdentityOp。带 RelativeErr 数值的可比算子(~466)误差全 ≈0、0 个真叶子算子发散(2 个独立样本 s0/s1 完全一致,多数 bit-identical)。

② 被排除的 35 个整层是量级差,不是 bug(方法学排除)
整层 TransformerLayer output 是残差和、含 SP,非 normed 算子:训练侧残差流 massive-activation max ~2.2e4 vs 推理侧 ~5.7,shape [S,1,H] vs [S,H] —— 这是不同模块边界 + LLaMA/Qwen 残差 massive-activation 现象,不参与比对,但不能据此宣称逐 tensor 全一致。

③ 样本数的坦白
token 完全匹配的干净可比样本通常只有 ~2 个(多数 prompt 的 train/infer prefill token 数不完全对齐)。run_megatron_compare.py 只跑 good[0] 一对;要多样本统计通过率用 batch_compare.py / run_megatron_compare_multi.py。

⚠️ 已知问题(compare 数据来源的诚实交代):推理侧 vllm run 跑不久 —— 两种独立失败:全 offload 把 8B 优化器态压 CPU 触发 host-RAM OOM(exit137,关 optimizer_offload/grad_offload 已堵)+ in-loop validation 的 vllm rollout 集合通信挂死(EngineCore 卡 shm_broadcast.acquire_read,关 trainer.test_freq=-1 已避)。都非 dcu_probe、非数值问题。compare 只用崩/挂之前的早期 step 产物(实测 0 NaN、有效),不期望长跑。

① 为什么 0.8 megatron 能直接喂 pt_compare
megatron 后端推理走 das vllm 0.11,它的 dump 模块序和训练侧 mcore/TE 能一一单调对上 —— 没有"训练侧缺失、位置又交错"的模块。所以配对好、挑好样本后,直接 pt_compare(consistent_check=True, backend="megatron"),dual_monotonic_sort 一次就过,不崩。这和 0.7 megatron 是同一套(都用 das vllm 0.11、都无过滤)。

② 为什么 FSDP 0.7 必须多一步过滤
FSDP 0.7 推理走 das vllm 0.18.1,推理 dump 里比训练侧多出 72 个训练侧无对应、且位置交错的模块(Triton.kernel_unified_attention×24 + reshape_and_cache×24 + 独立 rotary_emb×24)。不剔它们,pt_compare 的 dual_monotonic_sort 因两侧位置无法同时单调递增而 raise Conflicting comparison data → 崩。所以 run07_filtered.py 要先把它们过滤掉(338→266)才喂 pt_compare。

③ 底层工具是同一个,只 backend 参数不同
三个后端用的都是同一个 pt_compare,只是 backend 参数不同(megatron 用 MEGATRON_MODULE_MAP、fsdp 用 FSDP_MODULE_MAP)。megatron 版的脚本因此更短、更直——省掉了那道过滤,把精力全放在配对与样本挑选上。0.8 与 0.7 的 megatron compare 脚本几乎逐行相同。

一句话记住 0.8 megatron vs FSDP 0.7 的 compare 差异:
pt_compare = dcu_probe 官方比对工具(核心能力,两后端共用,只 backend 参数不同) run_megatron_compare.py(0.8/0.7)= 4 步·无过滤:配对 → 挑样本 → 直接喂 pt_compare(backend=megatron)→ 统计 [0.8: 1083 个 99.4% <1%] run07_filtered.py(FSDP 0.7)= 5 步·多一步过滤:配对 → 挑样本 → 剔 72 交错模块 → 喂 pt_compare(backend=fsdp)→ 统计 [98/98 <1%] 差异根因 = 推理侧 das vllm 版本:megatron 用 0.11(干净)、FSDP 0.7 用 0.18.1(72 交错模块)
